## 1. Separate entitlement, filing authority, and collectible economics before scoring  `🏷️ OPERATING_FRAMEWORK`

Start with three queues, not one refund spreadsheet. The drawback queue requires import entries, duty components, export or destruction evidence, claimant rights, and a qualifying route under 19 U.S.C. § 1313. Unused merchandise, manufacturing, and rejected merchandise have different conditions; an eight-digit HTS match alone never establishes substitution eligibility. For a qualifying 99% recovery, $100,000 of eligible paid duties produces a $99,000 collectible base and a $29,700 fee at 30%, before documentation and broker costs. Antidumping and countervailing duties are excluded under 19 U.S.C. § 1677h; other tariff measures require measure-specific eligibility research. The tariff-correction queue distinguishes an eligible pre-liquidation Post-Summary Correction from a post-liquidation protest under § 1514. A $50,000 supported overpayment produces a $15,000 fee only if the correction or protest yields that refund. The settlement queue starts with the certified class definition, covered purchases, release provisions, administrator instructions, and claim deadline. A client's $2 million purchase ledger is evidence, not a distribution estimate. A realized $20,000 distribution produces a $6,000 fee at 30%. Never add those purchases, refunded duties, or settlement pools to operating revenue. Score each lane on eligible dollars, evidence completeness, deadline slack, and expected collection delay before assigning scarce contractor hours.

Build twelve mapped workstreams around those queues: unused-merchandise drawback identification; manufacturing drawback linkage; rejected-merchandise drawback screening; export-document reconstruction; substitution eligibility reconciliation; classification correction; valuation correction; origin and preference correction; timely liquidation protest preparation; B2B antitrust purchase reconstruction; interchange settlement claim packaging; and freight_detention_audit_contingency. These are operating mappings, not twelve independent entitlements to the same dollars. The last identifier is the supplied TRACK_1 play, Automated Parcel, LTL Freight & Tariff Overcharge Contingency Auditing. Treat it as a shared ingestion and referral engine while preserving separate carrier and customs contracts. Price documentation before accepting an apparently lucrative file. ## 2. Implement six ledger modules with serialized writes and immutable evidence  `🏷️ OPERATING_FRAMEWORK`

The reference below uses Python's sqlite3 module, integer cents, and a single local SQLite database. Execute the six cells in order in one Python namespace; later cells define functions rather than inventing sample receipts. Each worker opens its own connection through connect(), and every mutable business operation acquires BEGIN IMMEDIATE before reading state. SQLite therefore serializes competing writers, while unique economic keys, receipt references, and event keys reject duplicate economic effects. A busy timeout produces an explicit retryable failure, not an unlocked fallback. Keep the database on supported local storage; do not share its file over a network filesystem. For multiple application hosts, port the same invariants to PostgreSQL transactions with row locks and unique indexes. The source digest represents actual supplied bytes, while the economic key represents the underlying entitlement rather than a filename. A corrected document needs a controlled amendment process, not a fresh case that reserves the same dollars twice. The compact reference intentionally freezes intake records. Production amendments should preserve prior versions, reviewer identity, reason, and a new digest. This design prevents duplicate writes within its transaction boundary; it does not turn an external customs portal into a transactional database participant.

Separate administrative state from money movement. A new case becomes verified only after an authorized reviewer records a complete evidence decision; it becomes filed only after a broker acknowledgment or administrator receipt is captured. The operator never treats an attempted upload as an accepted claim. External submission remains a supervised adapter boundary: before retrying after a timeout, search the broker or administrator system using the stable claim reference. If acceptance cannot be established, suspend submission and obtain confirmation instead of blindly transmitting again. This avoids promising exactly-once delivery to systems that offer no idempotency contract. The verification and escrow state machine records receipts as held until independent payment evidence establishes release; held is an informational restriction, not an instruction to open an operator-controlled escrow account. Client distributions remain with the payer, administrator, or client as the engagement specifies. The reference assumes one recovery receipt per independently identified payer transaction. Split batch payments upstream using a separately reconciled allocation register before adopting this model; do not manufacture reference suffixes to defeat uniqueness. A reviewer digest proves document linkage only. Application authentication, signing authority, and reviewer separation remain required controls around these callable functions and their database.

Revenue posts only when the contract's contingent fee is earned and the associated fee collection is evidenced under this example's cash-triggered terms. Gross recovery remains a memorandum amount, with operator fees and client allocation displayed separately. Assess ASC 606 principal-versus-agent presentation against actual contractual control; this scorecard uses earned operator fees, never underlying duties or settlement proceeds. Broker and contractor charges are expenses when the operator bears them, rather than an invented retained-share reduction to the canonical revenue figures. Fee rounding uses each case's cumulative released recovery, so splitting one payment into installments cannot create extra cents of revenue. The monthly view includes expense-only months and returns both owner profit and cumulative cash contribution. Its cost input must include all scenario costs, not merely recurring software subscriptions. Module six checks foreign keys, storage integrity, held-payment exclusion, allocation equality, and cumulative fee arithmetic. Add two-connection concurrency tests, duplicate replay tests, interrupted transaction tests, and restore drills before deployment. The snippets are a bounded reference, not an executed test report. Payment reversals and amended claims require explicit compensating-entry extensions; until those exist, stop automated processing of those exceptions and reconcile them in a separately controlled ledger.

**SOP — Standard Operating Procedure**

1. Acquire and reconcile evidence
   - Extract authorized source files and reconcile control totals before scoring.

2. Verify the correct recovery route
   - Send the prepared packet to the appropriately authorized specialist.

3. Submit and resolve deficiencies
   - Capture actual broker or administrator acceptance before advancing filing state.
