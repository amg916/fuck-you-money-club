## 2. Build a transactional inventory core and an auditable settlement ledger  `🏷️ OPERATING_FRAMEWORK`

Use the six modules below as an executable SQLite reference, not as a claim that a database can make unrelated marketplaces atomic. Copy their code cells in order into a Python module; create a connection with open_db and run qa_checks to exercise the local invariants. All amounts are integer cents, all inventory writes acquire BEGIN IMMEDIATE, and every physical entitlement has a stable source key. A reservation changes the lot and creates its order and transfer intent in one transaction. Repeated requests return the same order only when their business fields agree. Conflicting reuse fails explicitly. SQLite serializes competing writers across connections to the same database; do not distribute independent database copies to contractors. For PostgreSQL, replace the writer transaction with row locking and preserve every unique constraint. Busy errors are safe failures to retry using the original request key, never instructions to allocate a second lot. This reference avoids local double-allocation races; remote exchange acceptance remains a separate integration requirement. Without an authoritative cross-channel hold mechanism, publish the entitlement on one executable channel and keep other channels inactive rather than claiming asynchronous delisting eliminates simultaneous fills.

Verification records three explicit findings: ownership evidence, permitted transfer, and accepted transaction terms. The workflow then advances through verified, held, transferred, and settled states. The held state is an internal inventory reservation, not regulated escrow; an actual escrow provider requires its own agreement, account structure, and independently verified release evidence. Keep customer deposits in a liability account until the relevant performance obligation is satisfied. The dispatcher claims an outbox item before calling an external adapter and never holds a database transaction open during a network request. The adapter must use the supplied effect key with a provider-supported idempotency mechanism. If a provider lacks that mechanism, use the outbox as a manual execution queue with independent delivery confirmation. A timeout or process crash leaves an ambiguous operation for investigation, not automatic redelivery. Resolve it using the issuer or marketplace transfer record, matching the recipient and entitlement. No finite local code can prove remote exactly-once execution without cooperation from that remote system. The production objective is therefore single local ownership, durable intent, evidence-backed completion, and a fail-closed response whenever external execution cannot be established.

The ledger stores balanced debit-credit pairs with unique effect keys, preventing duplicate cash recognition while allowing a transaction to contain several pairs. It is an operational subledger, not an automatic determination of presentation under ASC 606. Assess principal-versus-agent status for each promise; the scorecard's 40% retained share is its analytical net contribution basis, not permission to net every contract in statutory accounts. Match bank deposits to exchange statements, order identifiers, payout fees, and provider transaction identifiers. A partially paid order remains delivered until cumulative receipts equal its documented net due. Record fee changes through a controlled adjustment process before settlement rather than silently modifying historical entries. Post refunds and reversals with new effect keys that reference the original entry; never erase the first record. Separate available cash, restricted event reserves, exchange receivables, supplier deposits, customer liabilities, and inventory writeoffs. The reconciliation view exposes order balances and account balances without converting unpaid receivables into spendable money. Production deployment also needs authenticated access, encrypted backups, restore tests, statement imports, monitored exception queues, and read-only reporting credentials. Those controls surround this reference and must be tested against the actual selected POS and exchange agreements.
