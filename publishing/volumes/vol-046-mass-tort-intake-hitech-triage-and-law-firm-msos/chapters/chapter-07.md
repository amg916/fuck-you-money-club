## 2. Build a six-module ledger with serialized writes and replay-safe transitions  `🏷️ OPERATING_FRAMEWORK`

Use the six reference modules below as one concatenated Python script, in table order. They implement the transactional core, not a public API or a medical-document repository. SQLite is suitable for this small team when the database resides on one local host and every writer follows the same transaction functions. Enable foreign keys, a busy timeout, write-ahead logging, and full synchronous commits; use one connection per worker. Each mutation acquires BEGIN IMMEDIATE before checking event identity or balances, so competing workers cannot both spend the same remaining receivable or advance one case from the same state. Database uniqueness independently blocks duplicate claimant identities, service invoices, and bank references. Store amounts as integer cents, never floating-point values. A repeated event with identical content returns without changing balances; reusing its key with different content raises an error. Event recording and business mutations commit together or roll back together. The included concurrency check exercises competing receipt allocations against one invoice. These local guarantees depend on the stated deployment boundary; do not place SQLite on a shared network filesystem or advertise distributed exactly-once delivery. The examples are supplied for execution and review, not reported as tests already run.

Keep three authorities distinct in application code: the authenticated actor, the preserved evidence reference, and the ledger transition. The reference assumes a trusted service adapter has already checked actor permissions and verified evidence references before calling its functions. Never expose those functions directly as unauthenticated endpoints. Intake scoring measures administrative completeness only; it does not predict recoveries or substitute for counsel's assessment. Advance cases through RAW, SIGNED, PROOF, and ACCEPTED using an expected-state comparison, with CLOSED as an explicit terminal alternative. SIGNED requires valid engagement evidence, PROOF requires reviewed source material, and ACCEPTED requires counsel's recorded decision. An invoice instead moves from HELD to BILLED after documented completion of its contractual service milestone. There is no operator escrow: any trust-account activity remains external with the law firm and cannot be posted through these functions. The held state is an administrative billing hold, not custody of claimant money. Revenue credits the MSO revenue account only when the service invoice is released; receipts debit bank cash and credit receivables. Operating payments debit expense and credit cash. Do not derive invoices from accepted-case counts, settle client claims through the ledger, or silently net provider refunds against previously recorded expenses.

Separate cohort attribution from posting month. A February receipt for January services belongs to January's operating cohort but February's bank reconciliation. The cohort view therefore explains earned revenue, operating expense, receivables, and collected cash by service cohort, while the monthly cash view explains actual cash movement. Record only reconciled bank transaction identifiers, namespaced by bank account, and retain the original statement in the protected evidence store. The reference accepts positive service invoices, receipts, and operating payments; it deliberately rejects overpayments rather than inventing a refund mechanism. Route credit notes, refunds, foreign currencies, and partial write-offs to a separately designed accounting integration with reviewed reversing entries before using those features in production. Never edit historical postings: immutable-entry triggers protect the journal, and reconciliation exceptions become assigned work items. For outbound provider requests, use a durable dispatch queue and the provider's idempotency facility when available; where it is absent, require a human check after an uncertain send instead of blindly retrying. The reference makes no external calls inside a transaction. Back up the database and document store under separate access controls, restore them into an isolated environment, and compare journal totals before declaring the recovery exercise complete.
