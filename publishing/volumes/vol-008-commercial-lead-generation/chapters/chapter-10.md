## 1. Build a durable event ledger before automating the inbox  `🏷️ OPERATING_FRAMEWORK`

Start with one event contract shared by research, permission tracking, qualification, appointment delivery, and billing. Each record needs an event identifier, source identifier, tenant identifier, subject identifier, source timestamp, receipt timestamp, evidence location, permitted purpose, and schema version. A Python receiver should authenticate the sender using the provider's documented signature procedure, reject stale signed requests, enforce body limits, and persist the event before acknowledging delivery. For a modest installation, sqlite3 transactions, a unique constraint on tenant plus source event, and an outbox table provide a practical foundation. Use json, hashlib, hmac, urllib.request, and logging for adapters; document the reverse proxy and worker runtime separately. Do not expose a development HTTP server as the production endpoint. A HubSpot or Salesforce timeout must leave an actionable outbox record rather than erase the prospect. Track received, validated, suppressed, reviewed, routed, accepted, disputed, and credited as separate states. State transitions carry actor identifiers and reasons. This structure turns retries into repeatable work instead of duplicate messages, appointments, or invoices. Restrict each worker to its tenant and required fields; a reporting job should never inherit messaging credentials simply because both jobs use the same database.

Permission is a versioned relationship, not a Boolean field copied between vendors. Store the channel, recipient, collecting entity, disclosed purpose, notice version, collection mechanism, and supporting evidence. A comment requesting a checklist supports responding to that request; it does not establish permission for unrelated automated calls or indefinite text campaigns. Evaluate the current permission state immediately before dispatch, even when a campaign was prepared yesterday. Suppression takes precedence over enrichment scores, account ownership, and scheduled retries. Under 15 U.S.C. 7704, commercial email requires accurate routing information, nondeceptive subjects, required identification and address information, and a functioning opt-out mechanism; implement removal immediately rather than designing around the statutory maximum. Calls and texts require separate analysis under 47 U.S.C. 227 and 47 CFR 64.1200, including technology, destination, purpose, and applicable permission requirements. Never treat a business contact label as a universal exemption. When an opt-out arrives, atomically update suppression and cancel pending dispatch records. Retain only the minimal suppression evidence needed to prevent recontact, with access and retention rules distinct from ordinary prospect profiles. Test races between unsubscribe events and queued sends before connecting additional inboxes to production.

Assign the full-time operator ownership of client definitions, consequential exceptions, and weekly economics. Give three contractors bounded responsibilities: source research and evidence checks, automation maintenance and delivery operations, and quality review with reporting reconciliation. Language models may extract attributes or draft replies, but deterministic code validates types, source references, routing limits, and prohibited actions. Treat retrieved pages and inbound messages as untrusted data, never executable instructions. A model cannot authorize a new recipient, change a client's qualification rules, or initiate a regulated referral. Measure automation against a sampled manual baseline. Suppose 1,000 repetitive tasks formerly required four minutes each: 4,000 minutes. Automation completes 760 tasks, with 40 selected for two-minute audits; 240 exceptions still require four minutes each. Retained labor is 1,040 minutes, a 74% reduction, while 720 tasks remain untouched, a 72% untouched completion rate. Report both measures because audited automation is not zero-touch work. Count incident repair, failed retries, and contractor review in the same denominator. If missing evidence increases, reduce routing autonomy before adding staff or purchasing more traffic. Seventy percent is an observed operating result, not a setting on the workflow canvas.

**SOP — Standard Operating Procedure**

1. Establish the baseline and event contract
   - Sample 1,000 repetitive tasks and document manual handling minutes.
   - Define tenant identifiers, evidence fields, permitted purposes, acceptance rules, and the exact event states before connecting production sources.
2. Run a shadow cohort without external dispatch
   - Process a representative batch through extraction, suppression, and proposed routing.
   - Have reviewers compare source evidence with structured outputs; measure unsupported claims, duplicate routing, exception minutes, and projected run costs.
3. Release a bounded, permission-supported cohort
   - Enable one source, one client, and a fixed daily dispatch ceiling.
   - Verify live suppression checks, review consequential exceptions, and test campaign pause plus dead-letter recovery before adding another source.
4. Reconcile outcomes and authorize measured expansion
   - Join accepted outcomes, reversals, review labor, and recognized service revenue.
   - Expand only after cohort contribution remains positive and client capacity is confirmed; preserve the canonical scenario totals in the annual ledger.
