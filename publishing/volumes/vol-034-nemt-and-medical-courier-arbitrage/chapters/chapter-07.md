## 2. Install the six-module ledger and make every mutation replay-safe  `🏷️ OPERATING_FRAMEWORK`

Use the six reference modules below as a narrow monetary control plane, not a replacement for credentialing, clinical systems, or a complete claims platform. Save each artifact under its named filename in one directory, initialize SQLite with schema.sql and views.sql, then import the Python functions from the dispatch integration. Python's sqlite3 module provides the database interface without additional packages. Store amounts as integer cents and treat payer plus service reference as the immutable intake identity. A changed quote under the same identity is rejected rather than silently overwriting previously authorized work. Every write acquires BEGIN IMMEDIATE before reading mutable balances, so concurrent writers serialize within this single database. A bounded busy timeout can produce a retryable lock error; it cannot produce a half-posted transaction. Keep the database on supported local storage, enable foreign keys on every connection, and restrict direct write access to these functions. Database permissions, encrypted storage, backups, and restore drills remain deployment responsibilities. The reference deliberately excludes patient names and addresses. Its identifiers point to access-controlled evidence in the operational system, reducing the information exposed through billing exports and support logs.

The state machine admits INTAKE or HOLD records into VERIFIED only when a reviewer supplies authorization, service, and custody-or-arrival references; it then recognizes the receivable and creates one driver payment instruction in the same transaction. Presence checks establish machine-readable completeness, not truth: an authorized reviewer must inspect the referenced evidence before calling release. The instruction's stable payout key crosses the payment boundary unchanged. An external bank adapter must support durable idempotency and status lookup before automated submission is enabled. If it does not, use controlled manual release and reconcile the bank reference before any retry; never claim that a SQLite transaction can make an unrelated bank transfer atomic. This design removes read-modify-write races inside the reference database and makes settled-payment recording replay-safe. It does not promise failure-free third-party services. A HOLD is an internal verification reserve, not a representation that customer money sits in regulated escrow. Driver payment terms still govern actual due dates. After recognition, corrections require separately designed reversal entries and supporting review; the supplied functions reject attempts to repurpose a released job or overwrite its evidence.

Recognition follows the supplied agent-style retained-share presentation: a $100 completed service debits receivables $100, credits driver payable $55, and credits retained revenue $45. Collecting the invoice moves $100 from receivables to cash without producing new revenue. Settling the driver reduces cash and the liability by $55 without charging that amount again against retained revenue. Actual principal-versus-agent presentation depends on the executed contracts and control of the promised service; the 45% convention here is the scorecard's explicit modeling basis. The reconciliation view reports gross recognized billings separately from retained revenue, expenses, bank cash, and outstanding liabilities. Bank references are unique across cash events, so a reused transaction reference cannot settle two jobs accidentally. Partial customer receipts are supported, while driver settlement is intentionally one complete payment per instruction. Split settlements require a distinct installment design before use. The QA module checks integrity, foreign keys, balanced entries, revenue allocation, instruction settlement, and the balance-sheet identity. Reconcile its cash output to an independent bank statement daily. The code is a reference artifact supplied for implementation; execution, load testing, and integration verification have not been performed here.
